# The book: Numerical Derivatives with Numerixx

A textbook and reference for `nxx::deriv`, the numerical-derivatives module of Numerixx 2, in LaTeX. These rules apply
to everything in `docs/deriv-book/` and override the repository's `CLAUDE.md` where they differ (they do not change
the library's rules). `BRIEF.md` holds the approved approach and the starting material; `PLAN.md` (written in stage 1)
holds the outline, the targets and the ownership, and wins over `BRIEF.md` once approved.

## Ground truth

What the book says about the library must be true of the library. In order of precedence:
1. `include/numerixx/deriv.hpp` and `include/numerixx/math.hpp` (the code and its comments);
2. the tests in `tests/` (what is verified, and with which references and tolerances);
3. `docs/deriv/design.md`, `docs/deriv/PHASE2_API.md` to `docs/deriv/PHASE5_API.md` (decisions and their evidence), and
   `docs/design.md` (the rules for every module);
4. `docs/deriv/DERIV_TUTORIAL.md`, `docs/deriv/DERIV_TECHNIQUES.md`, `README.md`.
Where they disagree, the higher one wins; report the disagreement to the author instead of choosing silently. The book
describes the library as it is; it does not promise features, and does not mention features the library lacks.

## Evidence rules (what makes the book withstand scrutiny)

- **Numbers.** Every number that comes from a computation (an error, an estimate, a count of evaluations, a step) is
  a `\val...` macro from `data/values.tex`, written by `tools/generate_data.cpp`. Never type such a number. Exact
  mathematical constants and textbook values (weights, error constants, 2^-52) may be typed, but must be checkable.
  `tools/check.py` warns about typed numbers; the editor clears every warning.
- **Figures.** Every plot reads `data/*.csv`; every data set is generated by the library (see `figures/README.md`).
- **Code.** Every listing is a compiled example in `code/`, quoted with `\snippet` (see `code/README.md`). No listing
  is typed into a chapter.
- **References.** Every citation is a real work that the evidence reviewer has checked against the work or a library
  catalogue (authors, title, year, publisher or journal, volume, pages, DOI). Never cite from memory unchecked: mark
  the entry `note = {UNVERIFIED}` until checked. Cite for every established method and result. Licensing: the
  library's code comes only from Numerixx 1.x and Boost.Math; the book may cite any literature, including Numerical
  Recipes, but must not reproduce its code.
- **Claims.** A claim about accuracy, cost or behaviour points to its evidence (a generated value, a test, a
  derivation, a reference). Distinguish what is proven, what is measured (and on what), and what is a rule of thumb.
- **Regeneration.** After any change to the library, run `numerixx_book_data` and rebuild; review the diff of `data/`.

## Style

- Teach before formalising: motivation, a picture or a small example, then the formula, then the caveats. Define every
  term at first use (in the text or with `\mnote`). Prefer one worked example that runs through a chapter.
- Precise, plain prose; short sentences; no hype. "We" is fine for the reader-and-author walking through an argument.
- Mathematics: numbered display equations for anything referred to; `\cref` for every reference; the notation of
  `macros.tex` (the notation guide in `PLAN.md`); new macros only in your own chapter, marked `%% NEW-MACRO`.
- Sidebars (`\begin{sidebar}[label=sb:...]{Title}`) for proofs, floating-point detail, implementation decisions and
  the like: self-contained, cross-referenced from the text, never required to follow it. A chapter has at most about
  three; Part II may refer to them.
- Margin material: `\sidenote` for asides (never `\footnote`), `\mnote` for glosses, margin figures for small plots.
- Plots where they show something words cannot: the error against the step, accuracy against the order, Ridders'
  convergence and its estimate, coverage. Each with a caption that states what to see.
- C++ in the text as `\code{...}`; listings via `\snippet`; examples realistic for engineers (a heat capacity from an
  enthalpy, Newton's method, a sensitivity), not toy one-liners only.

## Process: stages, each ending at a checkpoint with the author

1. **Plan** (editor): `PLAN.md` with the chapter outline and page targets, the notation guide, the lists of sidebars,
   figures (each with its data set), examples (each with its code file) and references to verify, ownership and the
   schedule. The author approves it. Nothing else is written before that.
2. **Evidence** (editor and authors): the data generator's data sets, the figure files and the compiled examples,
   before the prose that uses them. The author sees the figures.
3. **Drafting** (authors, in parallel): each chapter compiles on its own (`tools/check_chapter.sh`).
4. **Integration** (editor): one voice, notation, cross-references, length; the full build is clean.
5. **Review round 1** (all reviewers, in parallel): `reviews/R1-*.md`; the editor's `R1-decision.md`; the author sees
   a summary and decides on anything contested.
6. **Revision** (authors): `responses/R1-*.md`.
7. **Review round 2** (targeted, plus Codex): `reviews/R2-*.md`; final fixes.
8. **Release**: the author approves; commit and push.
Commit to `dev` at the end of each stage the author approves (the repository's workflow); never commit unapproved
prose as final.

## Build and checks

- Full build: `cmake --build --preset gcc --target numerixx_book` (regenerates `data/`, builds
  `build/gcc/docs/deriv-book/pdf/main.pdf`, runs `tools/check.py`). Without CMake: `bash docs/deriv-book/tools/build.sh`
  (does not regenerate `data/`). GCC needs `C:/Toolchains/GCC16/bin` first on PATH, as in the repository's CLAUDE.md.
- One chapter: `bash docs/deriv-book/tools/check_chapter.sh chapters/<id>.tex` until it prints `COMPILED OK`.
- Examples: `ctest --preset gcc -R numerixx_book`.
- Done means: the build and `tools/check.py` report no errors, every warning of `check.py` is cleared or justified,
  every example passes, and `chapters/zz-layout-test.tex` (with its template data set and example) is gone.
