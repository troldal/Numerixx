\chapter*{About this document}
\addcontentsline{toc}{chapter}{About this document}

This document is a textbook and a reference for \code{nxx::deriv}, the numerical-derivatives module of \nxx{}, a
header-only C++23 library of numerical algorithms. The module computes the first to the fourth derivative of a
function that a program can evaluate but cannot differentiate: a property model, the output of a solver or a
simulation, a correlation in someone else's code. It is written for engineers and scientists who are comfortable
with calculus and with C++ but are not specialists in numerical computation. The fundamentals are meant to be easy
to follow; the topics a user does not need to know, such as proofs, floating-point detail and the library's
implementation decisions, are in numbered sidebars that the surrounding text never depends on.

\section*{How to read it}

Part~I teaches. Its seven chapters build the methods up from one idea, Taylor's theorem, and are meant to be read in
order: where derivatives arise and what the library offers (\cref{ch:why}); the forward and the central difference
and their errors (\cref{ch:taylor}); why a smaller step is not always better, and how the step is chosen
(\cref{ch:rounding}); more points and one-sided rules (\cref{ch:stencils}); second to fourth derivatives
(\cref{ch:orders}); Ridders' extrapolation, the one method that estimates its own error (\cref{ch:ridders}); and the
library in use, with worked engineering examples and the pitfalls (\cref{ch:using}). One example runs through Part~I,
the heat capacity of nitrogen from its enthalpy, whose derivative is known, so that every error quoted could be
measured.

Part~II is the reference: every public name (\cref{ch:api}), every weight and constant (\cref{ch:tables}), and what
accuracy and cost to expect, where the methods stop working, and what the library guarantees (\cref{ch:guarantees}).
The appendices hold the floating-point facts and the derivations the sidebars cite; a notation table and a glossary
follow them.

A reader in a hurry has two shortcuts. \Cref{sec:why-summary}, ``If you read nothing else'', chooses a method for
the five situations that cover most uses and gives the two checks every call needs. And the
\hyperref[ch:quick-reference]{quick-reference page} (page \pageref{ch:quick-reference}) is the interface on one
sheet: the calls, the result, the failures, the method choice, the checks and the pitfalls that matter most.

\section*{The evidence}

Every number in this book that comes from a computation was produced by the library itself, apart from a few
attributed figures of its design record and tests: a generator program in the book's sources runs \code{nxx::deriv} and writes the values, the data behind every plot and the
bodies of the tables, and the text quotes them by name; at every run it also checks the weight tables and the
thread example against independent evaluations. Every code listing is quoted from a
compiled program that runs as a test of the library and checks what the text claims about it, with two exceptions:
the declarations of \cref{ch:api} are transcribed from the library's header and checked against it at every build,
and the CMake snippet of \cref{sec:using-call} is quoted from a file the book's build does not configure. The book
describes the library as it is; a missing feature is named as deferred.
